## V5（开发中，尚未发布）

### 检测与裁切

- 已登记共享边同时绑定相邻 END/START 时，两侧继续使用原有跨幅或联合坐标依据，避免单侧纹理
  角色误挡 Contact。冲突材料 component 取消正权限后，完整材料对的相反角色反证仍保留并阻止批准。
- 普通间隔只绑定一侧时，仍核对同一端点关联的唯一已登记 overlap 伙伴；完整走廊内的原生负 gap
  继续作为反证，避免单边 Grid 遮蔽已生成的 overlap 提案。材料冲突与 Review 门槛继续保留。
- 必需边界提出的位置解释不再因额外观测拉偏而提前删除；独立核验原必需集合后，仅剔除不相容的
  可选绑定。原物理区间、完整反证和自动批准门槛不变。
- 正常分隔材料的有序边缘对可在单边纹理角色相反时提出原子位置假说；原像素角色保持不变，
  坐标权限按实际所选角色核验，两高度材料只能从独立获权的一侧传递一次，并继续接受完整域检查。
- 完整跨幅的直接边界可凭原始测量闭合的物理直线域测试自己的位置 seed，避免统计残差提前删除
  真实边界；额外补边、局部线及宽缓材质线仍按原门槛筛选。角色、位置残差、完整保护和自动批准
  继续独立核验。
- 短片条两处材料位置提出的 pitch，须通过既有独立 ordinal/phase 闭合后才提交；失败时保留材料
  假说和原有界模板提案，撤销该 pitch 权限并保持 Review，不以未闭合校准覆盖原位置系统。
  闭合检查先核验候选的直接坐标权限；只有投影后保留的独立获权 anchor 才能闭合，弱边缘的
  raw 匹配成功不能提前授予 pitch 或 phase 权限。
  前置位置拟合触发 producer bound 时直接保留硬失败与原工作量 receipt，不重启位置搜索。
- 模板位置拟合在剔除离群观测后，按重拟合后的几何重新核查同一阈值；保留原生身份与必需绑定，
  剔除过程严格缩小原集合，并由已编译角色数限定求解次数，不重新匹配角色或新增候选。
- 分隔材料只使用两侧边界在该扫描线上实际相邻的观测；中间已有边界的扫描线不贡献材料支持，
  未成功拟合的已登记变化也保留为屏障。逐线原生坐标决定次序，避免全局 run 坐标误挡或漏掉
  中间变化，防止局部材料被误判为贯穿整张源图。
- 用户提供 format 并确认默认或显式 count；空白曝光格保留 ordinal，不猜格式、数量或空白。
  任一必需 slot 不安全时，整张 source 进入 `needs_review`。
- format/count 建立 source 共用的 W/H/pitch 模板，直接边缘保持原生坐标；校准 Grid、source W、
  aspect authority 与局部 Separator/Contact/Overlap 关系在各自权限内补全缺失信息。
- 整条片带与局部边界使用一次登记的有界测量。原生 16-bit 粗测保留弱材料变化，宽缓边按真实逐线
  支撑与完整物理直线域关联；不同观察身份、合法连接和保护范围完整保留，超出工作上限进入 Review。
- 每条源 TIFF 共用固定 `1.1W × 1.1H` 窗口，四边各 5% 留边包含全部基础保护。程序只选择位置，
  不叠加额外留边或小画幅固定下限。完整可见内容、倾斜角点与合法物理包络无法容纳时保留固定提案，
  不扩大窗口。共同 H 输出也必须用同一固定框保护全部获权解释。
- 只有真实 TIFF 外缘允许源边截断；内部 lane 越界不能通过缩框绕过。Deskew 是批准后的可选整理，
  不参与检测与 Gate；源边截断、旋转外包矩形和整数取整可能改变最终 TIFF 像素宽高。
- 固定窗口能够同时包含完整可见保护并留在真实 TIFF 内时，将中心限制到该交集，保留同样尺寸的
  完整窗口；无法同时满足时保留原包含或截断结果与预算失败。该规则同样用于共同输出。
- 内容保护限于 TIFF 中已记录的照片内容，不恢复片夹遮挡的画面。外侧颜色连续性和弱信号只作观测，
  不单独授予片夹身份或裁切权限。

### 诊断与黄金验证

- 首末照片具有原生跨幅或联合边界依据时，报告可按 START/END 四个端点角色类额外保留最多四份
  原生端点 Review 提案，完整保存各自原位置解释、反证、Cross 失败与保护预算。完整身份相同的解释
  只构建一次；每份使用独立初始 source 几何，最多一次已有界 Cross 求解与物化。原竞争、自动批准
  和正式输出选择保持原合同。
- 已登记的真实 TIFF 外缘允许既有 phase fit 保留首 START 或末 END 截断；内部 lane 越界和整格不可见
  仍拒绝。报告按终端方向与原 direct rank 1–3 额外保留最多六份完整源截断 Review 解释。
- 原生端点 Review 无法 compose 时，最多对每份解释作一次固定 intrinsic 绑定重拟合；原失败、原矛盾
  与全部 validation-only 反证完整保存。重拟合不取得 authority projection 或自动输出权限。
  报告统一保存 `independent_phase_review`，黄金分别评价最多十七份保留提案。

- 单侧固定 H 的 Review 提案优先使用实际扫描线覆盖全部已定位照片的边界；同等完整覆盖仍优先
  获权角色。上下文独立于自动使用权限，原反证、阻断原因、两份提案上限与工作量限制保持，报告
  重放核对上下文来源和保留位置。
- 晚期直接重拟合仍须通过同一 phase 残差上限；失败时保留投影前诊断位置和原退出事实，不取得
  投影资格。后续失败留下空备选槽时，可回填同一流程早期已生成的最高 rank terminal diagnostic，
  保留其原失败 projection，不替换真实竞争或增加 retained 上限。
- 高支持残差反证与首选的 phase/pitch 区间即使相交，只要完整 placement 身份不同，仍保留备选并
  阻止唯一胜出；投影已经终止的原解释也参加同一反证检查，保留原失败身份和 Review，不增加槽位。
  全部原生坐标已获权却与校准 Grid 联合约束冲突的更高支持解释，也保留为原生坐标反证。
  候选角色、残差与物理区间继续按原合同核查。
- 全部权限投影已终止时，空诊断备选槽可保留另一份已生成的不同解释，包含其原失败原因；不增加
  候选上限，不替换既有物理竞争，也不授予自动批准权限。
- 完整保护包络无法放入固定窗口时，原生提案保留已拟合位置及全部保护需求，预算失败继续阻止自动
  输出。恢复 pre-local 提案后，先重评其直接角色事实再测量共同 W，原失败与备选继续保留。
- 首选无法形成完整裁切而 canonical runner 已完整时，source proposal 引用备选的原几何；报告、
  Debug 完整性摘要与黄金比较保持一致。原角色、失败、Review 决定与自动输出权限保留。
- Debug Analysis 展示实际测量、首选、备选、有条件及独立原生端点 Review 提案、完整保护范围、来源和阻断原因，
  不生成正式照片，也不复用报告替代下一次正式检测。
- 开发黄金独立评价每份已生成 footprint，区分生成、资格与最终决定；同一 task 可以有多份安全提案。
  人工确认的可见边界严格阻断向内裁切，向外距离只作诊断，不按逐侧 5% 另设上限。
- 离线可用性排序按 source 分组，分开报告折外与样本内结果；开发分数不是校准概率，Runtime 未启用
  评分选择。人工 reference、source-SHA 绑定和评测角色不由自动工具改写。
- 序列、Cross、共同输出及最终采样保留可重放的 typed evidence 和工作量账本；报告回读复用当前
  几何 owner，不以自洽汇总代替完整物理保护检查。

### 运行与交付

- V5 只有一条 current-only production path。依赖版本由 `tools/install/dependencies.toml` 统一定义；
  安装器复用合格的全局依赖，并通过已识别的包管理器补齐或更新，来源不明时停止。
- 源码从仓库根目录使用 Python 命令启动；平台双击启动器用于发布包布局。中英文手册分别维护。
- TIFF I/O 保留 16-bit RGB、ICC、分辨率、受支持 metadata 与无损压缩，输出规范为 `Orientation=1`。
  输出先写 staging，再原子发布到全新目录；竞争、取消或失败保留已有目标并清理本次 staging。
  macOS 输出要求支持原子不覆盖操作的 APFS/HFS+ 卷，完成后可复制到 exFAT。
- `tools/verify` 统一承载工程、准确性、性能、平台与 Hook 验证；发布内容由
  `tools/release/manifest.py` 独占。发布资格必须按架构第 14 节绑定同一最终 commit，开发测试或
  安全 Review 不能替代 nominal 自动覆盖。当前 V5 未达到发布标准。

公开稳定版与历史版本见 [GitHub Releases](https://github.com/rrriiicccooo/X5-Crop/releases)。
